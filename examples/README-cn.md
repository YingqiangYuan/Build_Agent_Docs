# examples 索引, 六篇故事讲透一个思维模型

仓库根目录的 README 说的是这个 repo 技术上做了什么: 一个教 coding agent 去发现, 组织, 学习其他 coding agent 官方文档的 Agent Skill, 面向的是要用它, 要维护它, 要基于它扩展的开发者. 这里的 `examples/` 是另一件事, 面向的是没读过 repo 任何其他文档的外部读者, 目的不是再讲一遍这个 repo 的技术实现, 而是把造这个 repo 的完整经历收拢成一个能在面试里讲出来的故事, 以及故事背后一套可以带着走, 用在任何行业任何问题上的思维模型. 六篇按顺序读, 后一篇都建立在前一篇讲过的事实上.

> 🧭 **贯穿六篇的那一个核心理念.** coding agent 不是又一门技能, 它是那个凌驾于所有技能*之上*的技能: 掌握了它, 你就能学会任何领域, 解决任何问题, 因为 agent 能. 而驾驭它的方式, 是**无限递归解决问题**, 一套三层的习惯: (第一层) 把问题直接丢给 AI; (第二层) 别直接解, 造一个专解这一整类问题的专家 agent, 让它来解; (第三层) 连专家都造不出来, 就造一个能造专家的 agent. 这个 repo 把这个动作跑了整整**四**次, 一层套一层, 也就是 **"1 + 3"**: 三次内层递归 (每层一次), 包在一次更大的递归里. 这种嵌套本身, 就是你真的抓住了这套模型, 而不是撞见了一个巧合的证据.

> 🎯 **兑现点, 这套东西在面试里怎么*用* (第六篇第 5 节).** 这套能力是拿来**展示**的, 不是拿来描述的. 两种打法: **(A)** 被问到一个你已经很熟的技能, 提前用这套方法把它的专家重造一遍, 然后带着面试官走一遍你当时是怎么学会它的, 用一个能跑的真实成品, 证明你是个货真价实的 quick learner; **(B)** 被问到一个你*不懂*的领域, 就展示这套方法本身, "给我一点时间, 我能成为任何东西的专家". 真实的成品有视觉冲击力, 带着证据, 而一个只会说 "我学得快" 的候选人没有. (永远展示 `.claude/skills/` 下那个能跑的 Skill, 绝不展示 `examples/` 这个教学文件夹.)

## 01-why-this-repo-matters

先纠正一个容易被误解的事: coding agent 表面上是写代码的工具, 骨子里是那个凌驾于所有技能之上的技能, 学会了它你就能上手任何领域, 因为 agent 能. 在这个前提下, 这一篇讲清楚会用它跟不会用它的人之间那道两三代的代差, 定义三层的**无限递归解决问题**模型 (丢给 AI -> 造专家 -> 造一个能造专家的 agent), 并埋下 **"1 + 3"** 的预告: 同一个递归会在这个 repo 里跑四次, 而我们从第一次开始讲.

[这个 repo 到底要干一件什么事](./01-why-this-repo-matters/README-cn.md)

## 02-building-the-first-expert

只挖第一层, 而且只用 `claude-code-docs` 这一个专家举例. 从翻官方文档发现一个不起眼的 Copy page 按钮开始, 顺着线索找到全站的文档索引, 先验证这是不是一个官方可靠的机制, 再把发现写成一个 Skill 并测试, 完整看一遍造专家的过程长什么样.

[第一层专家, 是怎么被真的造出来的](./02-building-the-first-expert/README-cn.md)

[面试官追问了, 该怎么接](./05-answering-follow-up-questions/README-cn.md)

## 06-the-mental-model-recursive-decomposition

跳出这个 repo 本身, 把撑住整个故事的思维模型单独讲清楚: 无限递归拆解. 它把 **"1 + 3"** 的嵌套显式点出来, 论证这套模型能用在任何行业任何规模的问题上, 然后, 也是最实用的部分, 讲透在面试里真正*用*这套能力的**两种打法** (展示它, 而不是描述它), 最后补上最后一块: 学完这六篇, 真正要做的是把它内化成自己的能力.

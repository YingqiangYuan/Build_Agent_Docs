# Building Port Tools with a Generator

Once you have the documentation Skills and the coding-agent-concept-mapping knowledge base in place, the real work begins: migration — taking one agent's configuration in a project and porting it to another agent. That job falls to a family of port Skills. For every pair of agents, in each direction, you need two Skills: a `port-<source>-to-<target>` that actually performs the migration, and a `port-<source>-to-<target>-checker` that does a read-only audit of how complete the migration is, writing a gap report to the project's `tmp/review-port-<source>-to-<target>.md`. With three agents that can convert to each other pairwise, that's 6 directions, two Skills per direction, 12 Skills in total.

The key decision is that we don't hand-write those 12 Skills — we manufacture them with a `port-coding-agent-skill-generator`. Maintaining 12 files by hand invites drift, so the generator only knows about two templates: a port template and a checker template, with every shared behavior living in the templates. A developer runs a command like `/port-coding-agent-skill-generator cc to cdx` (or spells it out as "claude code to codex"), and the generator parses out the source and target agents, plugs them into the templates, and generates (or overwrites) the two `SKILL.md` files. If you want to change how all the port Skills behave, you change the template and regenerate — you never hand-edit a generated file.

There's a deliberate line drawn here: the list of agents is hardcoded, but the list of concepts is not. Which agents exist, their canonical names, slugs, and corresponding docs Skills — that list is small and stable; adding a fourth agent is a rare event, so it's fine to bake that lookup table into the generator. But the set of portable concepts (project prompt, settings, skills, hooks, MCP servers, subagents, permissions, and so on) keeps growing, so the templates never hardcode a concept list. Every time a generated port or checker Skill runs, it reads the concept list fresh from the coding-agent-concept-mapping index, follows it to look up the docs, and then either performs the migration or writes the audit report. That way, adding a new concept never requires touching any of the 12 Skills — it takes effect automatically as soon as coding-agent-concept-mapping is updated.

# 06 — Demo Playbook

> **Cardinal rule for this repo (from the project owner + `examples/03` § 7):**
> the **only** thing you ever put on screen is the **live skills under
> `.claude/skills/`** and, if useful, the four English `docs/0X-*.md` overviews.
> **Never** open `examples/` in front of an interviewer — that's where you
> *rehearse* the story, not the material you show. See the Do-NOT-show list below.

---

## Wow features (in priority order)

1. **A live, self-updating documentation expert.** Open
   `.claude/skills/claude-code-docs/SKILL.md`, then ask it a question about a page
   you've never opened and watch it fetch the live index and cite a real doc URL.
   *Why it lands:* it's not a screenshot or a slide — it's a real file that runs,
   and the answer is provably current. This is the single strongest beat.
2. **The three-layer generator pattern.** Show that `write-agent-skill`,
   `concept-mapping-builder`, and `port-skill-generator` are each a *generator*
   that produced many outputs. *Why it lands:* it demonstrates architectural
   judgment (build the mechanism, not the answer), which is what senior
   interviewers actually probe for.
3. **A real migration + independent audit.** Run a `port-*` doer on a sample
   project, then its `-checker`, and open the `tmp/review-port-*.md` gap report.
   *Why it lands:* it makes the abstract "portability / no lock-in" claim concrete
   and shows the doer/checker separation of concerns.

## Recommended sequence (golden path)

### 5-minute version
1. **Open** `.claude/skills/claude-code-docs/SKILL.md`. **Say:** "This is a Claude
   Code expert that never goes stale, because it reads the live official docs each
   run instead of memorizing them."
2. **Scroll** to the Procedure section. **Say:** "The rule is: read the index,
   fetch 1–3 pages per question, cap at 9, cite sources."
3. **Run** a live question about an unfamiliar page. **Say:** "Notice it cites a
   real URL — that's grounding, not recall."
4. **Close:** "The real value isn't this one expert — it's that the same
   discover→verify→encode→test method builds an expert for any changing tool."

### 15-minute version
1–4. The 5-minute version above (Layer 1).
5. **Open** `.claude/skills/concept-mapping/ref/03-skills.md`. **Say:** "Layer 2
   lines up the same concept across all three tools — and every cell was sourced
   by asking the Layer-1 experts, never from memory. Look at the `Porting-in
   notes` row: it's keyed by destination, which keeps it O(N) instead of O(N²)."
6. **Open** `.claude/skills/port-skill-generator/ref/port-skill-template.md`.
   **Say:** "Layer 3's 12 migration skills aren't hand-written — they're stamped
   from this template. Change behavior once, regenerate all twelve."
7. **Run** a `port-*` doer + `-checker` on a sample project; **open** the
   `tmp/review-*.md` report. **Say:** "The migrator never grades its own work —
   a separate read-only checker writes this gap report."
8. **Close** with the mental model: "Every layer is the same move — build a
   mechanism that keeps producing the answer and pull the layer below fresh — which
   is why a doc change or a new concept ripples up automatically."

## Audience tailoring

| Audience | Recommendation |
| :--- | :--- |
| **Hiring manager, AI-tooling / dev-productivity / platform role** | Full 15-min. Emphasize Beats 5–6 (the generator pattern, O(N) design) and Round-3/5 tradeoffs from `05-interview-playbook.md`. This is the ideal fit. |
| **Hiring manager, role unrelated to AI tooling** | Don't force it. Either give the **5-min** version framed around the *method* ("here's how I make AI teach itself — the domain here is coding tools, but it transfers"), or **skip the repo entirely** and tell the `examples/05` § 6–7 transfer stories (paper-tracking, team Scrum Master) instead. A poor-fit deep-dive reads worse than a crisp method pitch. |
| **Peer engineer** | 15-min, but linger on the tradeoffs: SPA-manifest vs live-`llms.txt`, destination-keyed notes, doer/checker split, hardcoded-roster/non-hardcoded-concepts. |
| **Non-technical stakeholder** | 5-min, value-only: "an assistant that always knows the current way to use our tools, and can move our setup between tools so we're never locked in." Skip the internals. |

## Recovery moves (when a beat fails live)

- **A live doc fetch is slow or errors.** Say: "The network's being slow — the key
  point is the *mechanism*," and scroll the `SKILL.md` Procedure section instead;
  the code is the proof, the live call is the flourish.
- **Antigravity fetch 404s mid-demo.** That's a teaching moment: "This is exactly
  the stale-manifest case — I'd run `/antigravity-docs-index-builder --force`."
  Then pivot to `claude-code-docs`, which fetches live and won't have this issue.
- **A `port-*` run produces an ugly diff.** Open the `-checker` report instead and
  frame it as "and here's how I'd *audit* that migration" — the gap report is the
  more impressive artifact anyway.
- **Screen-share unavailable.** Fall back to the `examples/03` § 7 verbal script
  (delivered from memory, not shown) — but note you'd normally show the live skill.

## Rehearsal questions (the demo skill drills these)

1. "Why does this never go stale? Show me where that's enforced." (→ index re-read
   rule in the `SKILL.md`.)
2. "Which parts did the AI do vs you?" (→ `05-interview-playbook.md` Q5.2 / four
   decisions.)
3. "What happens when Claude Code renames a doc page?" (→ picked up on next index
   read; nothing to change.)
4. "Why is Antigravity handled differently?" (→ SPA, local manifest, `/assets`
   content URLs.)
5. "How do you add a fourth tool?" (→ generators + concept column only; never the
   12 generated skills.)

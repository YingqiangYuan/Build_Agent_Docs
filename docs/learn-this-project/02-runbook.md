# 02 — Runbook

> **Scope note.** There is **no server, build, or long-running process** here.
> "Running" this project means **invoking its skills from inside a coding agent**
> (primarily Claude Code). The Python toolchain (`mise` + `uv`) exists only to
> give the repo a reproducible skeleton; the `httpx2` dependency is not exercised
> by the skills. So this runbook is split into two halves: (A) the trivial
> Python env setup, and (B) the part that actually matters — how to *run the
> skills*.

---

## A. Python environment (optional scaffolding)

### Prerequisites
| Tool | Version | Install |
| :--- | :--- | :--- |
| `mise` | latest | `curl https://mise.run \| sh` (see <https://mise.jdx.dev>) |
| Python | 3.12 | `mise use python@3.12` (declared in `mise.toml`) |
| `uv` | latest | `mise use uv@latest` (declared in `mise.toml`) |

`mise.toml` is the source of truth for both the runtime versions and the tasks.

### First-time setup
```bash
# from the repo root
mise install            # installs python 3.12 + uv per mise.toml [tools]
mise run venv-create    # -> uv venv         (creates .venv/)
mise run inst           # -> uv sync --all-extras  (installs deps)
```

### Day-to-day commands
| Task | Command | Underlying |
| :--- | :--- | :--- |
| Create venv | `mise run venv-create` | `uv venv` |
| Install deps | `mise run inst` | `uv sync --all-extras` |
| Remove venv | `mise run venv-remove` | `rm -r .venv` |

That is the entire Python surface. You do **not** need it to use the skills.

## B. Running the skills (the real workflow)

The skills live under `.claude/skills/`. Claude Code discovers them
automatically. Invoke a skill either by its slash command (e.g.
`/claude-code-docs`) or by asking a question whose wording matches the skill's
`description` (auto-invocation).

### Layer 1 — ask a documentation expert
```
/claude-code-docs how do I define a hook that runs before every Bash call?
/codex-docs        what sandbox modes does the Codex CLI support?
/antigravity-docs  how do I configure an MCP server in Antigravity?
```
Each reads its index, fetches 1–3 relevant pages, and answers with citations.
If it hits the 9-page cap without a confident answer, it stops and asks whether
to keep going.

**Refreshing the Antigravity index** (only when its docs change / a fetch 404s):
```
/antigravity-docs-index-builder            # rebuild if the JS bundle changed
/antigravity-docs-index-builder --force    # rebuild even if unchanged
```
Or run the script directly:
```bash
python3 .claude/skills/antigravity-docs-index-builder/scripts/build_manifest.py --force
# set ANTIGRAVITY_BUILD_DATE=2026-07-04 to stamp the manifest _meta date
```

### Layer 2 — query the concept map
```
/coding-agent-concept-mapping how do skills map across the three tools?
/coding-agent-concept-mapping hooks
```
Answers come from `.claude/skills/coding-agent-concept-mapping/ref/` (index → detail file).
To **change** the knowledge base, use the builder instead of editing by hand:
```
/coding-agent-concept-mapping-builder 05-hooks       # refresh one concept file, then the index
/coding-agent-concept-mapping-builder subagents      # add/refresh a concept
```

### Layer 3 — run or audit a migration
```
# generate/refresh a doer+checker pair (explicit invocation only):
/port-coding-agent-skill-generator cc to cdx          # -> port-claude-code-to-codex (+ -checker)

# run an actual migration on a target project:
/port-claude-code-to-codex /path/to/some/project

# audit how complete a migration is (read-only; writes a report):
/port-claude-code-to-codex-checker /path/to/some/project
```
The checker writes its gap report to
`tmp/review-port-claude-code-to-codex.md` inside the *target* project and
changes nothing else.

## Tests

There is **no automated test suite** (`_(not enough signal in the codebase yet —
fill in when this becomes true)_`). The project is validated the way `examples/02`
describes: **manual black-box testing** — after writing/regenerating a skill, ask
it questions about pages it has never seen and confirm it locates the right
source and answers with citations. Suggested smoke checks:

| What to verify | How |
| :--- | :--- |
| A doc expert can find an unseen page | Ask `/claude-code-docs` about an obscure setting; confirm it cites a real doc URL. |
| The 9-page cap works | Ask a deliberately broad question; confirm it stops and asks rather than fetching endlessly. |
| The Antigravity manifest is fresh | Run the index-builder; confirm no `content_url` 404s. |
| A generated port pair has no stray placeholders | `grep -R "{{" .claude/skills/port-claude-code-to-codex*` returns nothing. |
| Concept files follow the standard | Spot-check a `ref/0X-*.md` has a `Porting-in notes` row + a `Sources` section. |

(Adding a real `tests/` harness that subprocess-runs these checks is the first
item in `03-elevation-roadmap.md`.)

## Common failures and fixes

| Symptom | Likely cause | Fix |
| :--- | :--- | :--- |
| `antigravity-docs` returns 404 on a page | Stale `docs-manifest.json` | `/antigravity-docs-index-builder --force` |
| Index-builder: "could not find `main-<hash>.js`" | Antigravity app shell markup changed | Patch `find_bundle_name` in `scripts/build_manifest.py` |
| Index-builder: "DOCS_STRUCTURE not found" | Bundle record shape changed | Patch `parse_structure` in the same script |
| A port skill uses a concept that isn't migrated | Concept list read at runtime from Layer 2 | Add/refresh the concept via `/coding-agent-concept-mapping-builder`; the port skills pick it up automatically |
| A doc expert answers from memory / invents a URL | Skipped the index read | Re-run; the `SKILL.md` rule is "index first, never invent URLs" |
| Generated port skill still shows `{{PLACEHOLDER}}` | Generator substitution missed | Re-run `/port-coding-agent-skill-generator <src> to <tgt>` |

## Where to look when something breaks

- **Doc-expert behavior** — the relevant `.claude/skills/<name>/SKILL.md`
  "Procedure" section is the spec of what it should do.
- **Antigravity manifest** — `.claude/skills/antigravity-docs/references/docs-manifest.json`
  (`_meta` records the source bundle + build date); regenerate with the builder.
- **Concept facts** — the `Sources` section at the bottom of each
  `coding-agent-concept-mapping/ref/0X-*.md` tells you which doc page a claim came from.
- **Port behavior** — never debug a generated `port-*/SKILL.md`; read
  `port-coding-agent-skill-generator/ref/port-skill-template.md` (or `checker-skill-template.md`).
- **Migration audit output** — `tmp/review-port-*.md` inside the target project.
